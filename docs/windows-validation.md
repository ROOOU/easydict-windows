# Windows 优化与验收记录

日期：2026-10-16 至 2026-10-18。接续 Claude 会话 `64e41e35-2514-4fa0-85c7-ce9f3c4d030a`，
以及 Codex 会话 `01a14474-1d83-77e2-b7ca-c95809e33a5f`、`01a14558-7e47-7052-8e03-e9651d2a320f`、`01a147e1-9443-7200-afc8-9fc74c1d95d5`。

## 结论

当前是可构建、核心翻译能力可用的 Windows 移植版，**不能称为已经完全完善或与 macOS 完全对等**。
自动化单元/传输测试不等于真实 Windows 桌面验收；下文分别列出实现、已验证与未验证内容。

## 本轮修改

- **窗口隔离**：主窗口、迷你窗口和固定窗口各自持有查询运行状态。事件按窗口单播，不再向隐藏窗口广播同一请求；停止一个窗口不会停止另一个窗口。
- **过期结果与取消**：请求携带唯一 ID。旧请求的流式片段、完成通知以及清空后的迟到结果不再覆盖新内容；取消不会触发成功完成后的自动复制/朗读，也不再计入完成查询历史。
- **监听与设置同步**：修复异步监听在 React StrictMode 卸载后残留的问题。每窗口只保留一组设置监听，焦点刷新复用正在进行的读取；设置变更主动通知其他窗口。更改全局快捷键会重新注册，不必重启。
- **输入体验**：接通“粘贴后自动翻译”，保留选区替换语义；中文输入法组词期间不自动发出查询，确认候选字不会误触快捷键。查询完成后的自动朗读已接入。
- **窗口入口**：首次运行显示主窗口。划词按快捷键窗口设置打开，剪贴板入口会显示结果窗口；迷你窗口的托盘/快捷键入口也使用位置设置。主窗口与设置窗口不会再被强行移动到屏幕右侧。
- **设置导航与 OCR**：历史、收藏、关于入口导航到对应页面；截图 OCR、静默截图 OCR、剪贴板 OCR 派发到 OCR 窗口。截图前隐藏 OCR 窗口；静默识别复制文本但不主动打开结果窗口。
- **原生截图框选（第二轮）**：截图翻译、普通/静默截图 OCR 共用 Win32 框选器。先冻结桌面画面，拖动后只裁剪选中像素；Esc、右键、失去激活或显示布局变化均取消。使用每显示器 DPI 感知线程和物理坐标，支持左侧/上方副屏的负坐标。点击/极小选区不会退回整屏识别；整个进程同一时间只允许一个框选器。
- **OCR 取消与过期任务（第二轮）**：取消框选保留原识别文本/译文，原来隐藏的窗口不被强制打开，静默取消不改剪贴板；因 Alt+Tab、失去鼠标捕获或显示布局变化取消时，不抢回焦点。OCR 窗口增加任务取消；编辑原文、关闭窗口或启动新识别后，旧识别/翻译结果与错误不再覆盖当前内容。取消是废弃结果，并不保证中断已经开始的 WinRT/HTTP 请求。移除无人发送的 OCR 全局事件监听。
- **截图性能与界面（第二轮）**：截图、框选消息循环与 PNG 编码均在阻塞工作线程运行；OCR 工具栏在窄窗口换行。识别操作的提示明确区分重新框选与重新读取剪贴板。
- **划词边界**：UI Automation 放到后台线程；没有选区时不再读取整段输入框内容，并拒绝读取受保护的密码控件。
- **真实可用性提示**：HTTP 服务、有道 OCR、服务端语言检测优化的未实现控件已禁用或说明；最初禁用的后台划词和图标控件在第八轮接入。隐私页明确区分本地历史和发送给翻译服务商的查询文本，并提示设置导出包含明文密钥。
- **首次可用配置**：新安装默认启用 Google、Bing、DeepL，不再默认启用依赖未随应用分发密钥的有道和内置 AI。已有用户服务选择保持不变。有道的密钥状态读取其真正使用的 `youdaoWebApiKey` 字段。

### 第三轮：Windows 设置保护（2026-10-17）

- **加密落盘**：整个设置文档以 Windows 当前账户 DPAPI 加密后写入版本化 JSON 外壳，临时文件也不包含明文设置。读取合法旧版 JSON 时先原子迁移；不创建含明文凭据的备份副本。加密失败不降级成明文。
- **保留损坏配置**：只有文件不存在才使用默认设置。解析失败、未知加密格式、解密失败或迁移写入失败均停止启动，并显示原生错误提示与配置路径，不让首次启动逻辑覆盖原文件。应用数据目录获取失败也不再退回当前工作目录。
- **可靠保存**：设置修改在同一锁内基于最新快照合并，持久化成功后才替换内存、刷新服务和通知窗口。保存失败通过命令和设置页横幅报告；服务配置、语言交换、重置、导入与服务排序也走同一路径。
- **安全导出**：默认清除 14 个顶层凭据字段和所有服务实例的 `apiKey`；只有用户开启“包含密钥”并确认才导出明文凭据。自定义端点、提示词及其他设置保留，不能将默认导出当作绝对无敏感信息的公开文件。
- **原生文件交互**：导入和导出使用 Windows 文件选择器；覆盖导入前明确提示会替换设置及凭据，不修改历史/收藏数据库。对话框权限仅授予设置窗口。禁止导出至应用数据目录，避免覆盖加密设置或数据库。
- **启动时序**：首次真实桌面检查发现设置页残留 `state not managed` 错误。原因是配置中的隐藏 WebView 也会提前加载并调用命令；现将五个窗口都改为延迟创建，先注册后端状态，再按原配置创建窗口，不使用定时重试掩盖竞态。

保护边界：DPAPI 不是独立保险库，通常要求原 Windows 账户和原电脑；同账户程序仍可能读取运行时解密后的数据。
历史数据库不在本轮加密范围内。跨设备迁移应使用导入/导出，旧程序不认识加密格式，**降级前务必导出备份**。
导入不含凭据的文件会清空现有凭据，界面会要求确认。丢失原账户的解密能力时，应用不能恢复这些凭据。

### 第四轮：系统集成事务与状态（2026-10-17）

- **快捷键冲突不再静默失败**：设置修改先保留新组合，成功后才释放旧组合。原生注册或持久化失败时逆序回滚，设置内存和磁盘不提交；回滚自身失败也会显示在错误信息中。不再先注销全部快捷键。
- **启动注册状态可见**：先初始化全局快捷键，再创建 WebView。设置页读取本应用实际注册情况，逐行提示占用或无效绑定；空绑定仅表示未设置，不再冒充注册失败。
- **系统拦截时仍可编辑**：真实桌面测试确认，被其他进程注册的组合不会送达 WebView 的键盘捕获。各行增加“输入”入口，允许手动填写组合并在保存时走相同的原生占用检查；不添加全局键盘钩子。不因其他未修改快捷键的启动冲突阻止逐项修复。
- **统一验证**：使用原生解析器和规范化 ID 检查别名/修饰键顺序导致的重复组合，拒绝保留键 F12 和会拦截正常输入的无修饰/仅 Shift 全局组合。旧配置的多个无效绑定可逐项修复。小键盘 Enter 捕获保留 `NumpadEnter`。
- **尊重系统自启动选择**：启动及无关设置修改不再按保存偏好强行重写自启动。开关显示系统实际值，偏好不一致或读取失败时明确说明；用户显式点击、导入或重置时才应用请求。失败回滚使用操作前的系统实际值，而不是可能过时的偏好。
- **文件选择器默认目录**：空路径和相对路径从用户 Documents 目录开始，导出默认文件名为 `easydict-settings.json`；用户指定的绝对路径和网络路径保持不变。目录解析失败显示错误，不回退到程序安装目录。

### 第五轮：应用内快捷键一致性（2026-10-17）

- **收尾中断的桌面测试**：第四轮在正常换绑检查后中断；本轮实际读取界面确认“输入翻译”仍为测试组合 `Ctrl+Alt+B`，已通过设置页恢复为原 `Alt+A`。
- **录制与匹配共用规则**：将物理按键转换移至 `src/shortcuts.ts`，设置页和查询窗口共同使用。修复 `Ctrl+Shift+1`、带 Shift 的标点组合能保存却无法触发，以及键盘布局输出字符与物理按键不一致时触发错误操作的问题。
- **小键盘隔离**：小键盘数字、Enter 和运算符不再误触发主键盘数字、Enter、标点或导航快捷键；NumLock 关闭时仍按物理小键盘键匹配。补齐小键盘运算符录制。
- **手动输入与输入法边界**：应用内匹配支持后端接受的 `Option`、`CommandOrControl`、`Num1`、`NumPlus` 等别名，拒绝空分段/多个主键/错误顺序；录制和匹配均忽略输入法合成事件与 `keyCode=229`。保留原 `Ctrl+plus` / `Ctrl+underscore` 字号操作。
- 没有添加依赖；合并重复实现后，前端源码净减少约 70 行。

### 第六轮：划词翻译读取与结果可见性（2026-10-18）

接续 Codex 会话 `01a14993-b5ba-7440-9c73-015f57a9a44d`。用户反馈「基本的划词然后翻译都没实现」，
复现后确认是两个独立缺陷叠加：选区读不到，以及服务结果到达时被前端隐藏。

- **选区读取改为双路径**（`src-tauri/src/platform/selection.rs`）：先走 UI Automation 的
  TextPattern；普通 `EDIT`、WinForms 文本框等不提供 TextPattern 的控件改为模拟一次 `Ctrl+C`，
  读取后把剪贴板按格式原样放回。备份复制每个 `HGLOBAL` 剪贴板格式（文本、HTML、RTF、文件列表
  等），`CF_BITMAP`/图元文件等非全局内存格式无法复制时记录告警；若剪贴板完全无法备份或只含
  无法备份的格式，则放弃读取而不是清空用户内容。
- **按键卫生**：模拟复制前等待 Alt/Shift/Win 释放（超时后补发按键释放），避免全局快捷键的
  `Alt` 与 `Ctrl+C` 组合成 `Ctrl+Alt+C`；用户已按住 Ctrl 时只发送 `C`，不释放用户仍按住的键。
- **控制台保护**：前台窗口是 `ConsoleWindowClass`、Windows Terminal 或 mintty 时不做 `Ctrl+C`
  回退，因为那里的 `Ctrl+C` 是中断正在运行的程序而不是复制。
- **密码框保护**：UIA 的 `IsPassword` 与原生 `EDIT`（含 WinForms 子类）的 `ES_PASSWORD`
  样式都会拒绝读取。
- **设置接入**：`enableForceGetSelectedText`（设置 → 通用 →「无法读取选区时改用复制」）此前
  没有读取点，现在控制剪贴板回退，默认开启。关闭后只使用 UI Automation。
- **空选区反馈**：读取失败时结果窗口显示「没有获取到选中的文字，请先选中文本再按快捷键」，
  不再静默无反应。
- **结果卡不显示（本轮发现的独立回归）**：`query::run_one` 完成时用服务新建的 `QueryResult`
  覆盖加载中的结果，而新对象 `is_showing=false`；前端按 `isShowing` 过滤，导致**所有窗口**
  在结果返回的瞬间把卡片隐藏，只剩空状态。现在最终结果继承加载结果的 `is_showing` /
  `manual_show`，有译文时强制可见；无译文且为警告错误时仍隐藏。新增两条回归用例，
  其中「完成结果保持可见」在旧实现上失败、修复后通过（已做变异验证）。
- **查询日志**：查询开始/结束按窗口记录请求 ID、文本长度和语言；每个服务的可见性与文本长度
  降为 debug，便于以后区分「没有结果」和「结果被隐藏」。

### 第七轮：划词的剪贴板与隐私保护（2026-10-18）

接续本地会话 `6a419ae9-eae2-4500-926f-db94c5bcbf8d`。本轮修正第六轮读取流程的安全边界，
**不是鼠标自动划词功能，也不沿用第六轮截图作为新版本的验收证据**。

- **拒绝降级绕过保护**：UIA 明确报告密码、无法确认密码属性、无法获取焦点或访问失败时直接结束，
  不再把这些失败当成普通“无选区”而调用 `Ctrl+C`；原生密码框检查提前到整个流程入口。
- **完整备份或不复制**：任何格式无法读取/复制、格式枚举失败均放弃整个备份。
  位图、调色板、图元文件、嵌套图元句柄、私有/owner-display 格式不按普通 HGLOBAL 字节复制。
  即使同时存在文本，也不会只恢复文本后丢掉其余格式。设置说明与失败提示同步更新。
- **正确的剪贴板所有者**：用不可见的 message-only 窗口打开剪贴板并执行恢复；
  不再依赖 `OpenClipboard(NULL)` + `EmptyClipboard` 后没有所有者的 `SetClipboardData` 操作。
- **并发与焦点边界**：同一时间只允许一次选区读取，不排队执行迟到的复制；
  UIA 前后、等待按键释放及发送前检查前台窗口/焦点，变化后废弃。
  Alt/Shift/Win 仍按住超过等待时限时直接退出，不再伪造用户按键释放。
- **恢复不覆盖新复制**：备份、读取及恢复均在打开剪贴板期间核对版本；
  只接受原目标进程拥有的复制结果，恢复前发现新版本则保留新内容。

限制：无法原子化控制另一个程序的异步复制。超时后的迟到写入、同一进程内同时复制、
复杂延迟渲染、读后恢复时系统拒绝访问等仍需真实应用验收，不能宣称“剪贴板绝不会变化”。
本轮未更改“翻译并替换”的剪贴板实现；该链路仍属于待完善项。

### 第八轮：自动划词与原版语义对照（2026-10-18）

- **原生图标**：新增 `platform/auto_selection.rs`，使用不激活、不进任务栏的 Win32 popup，
  不额外创建 WebView。支持拖选、双击/三击、Shift+点击，以及编辑控件内 Ctrl+A；
  本应用窗口和注入输入不触发后台读取。关闭设置时卸载鼠标、键盘和前台切换钩子。
- **有限后台工作**：钩子只派发事件，不在钩子里执行 UIA；鼠标移动只在图标可见时最多每 100 ms 处理一次。
  最多一个读取工作线程在途，仅保留最新待处理手势。关闭监听后仍保留一个等待消息的原生线程，
  没有剪贴板轮询或常驻读取定时器。跨进程 UIA 已开始的调用不能强制打断，结果可被废弃。
- **失效与安全边界**：输入、滚动、外部点击、前台切换及配置变化废弃旧选区；
  图标打开时使用已捕获文本而不是重新读取已改变的焦点。沿用第七轮密码、剪贴板完整备份与版本检查。
  自动模式的复制回退额外要求已知文本控件；仅 Ctrl+A 的读取还要求 Edit 控件。
- **设置语义纠正**：后台监听由 `autoShowQueryIcon` 控制，而不是 `autoQuerySelectedText`。
  后者只控制结果窗是否立即查询；关闭后只填入原文，不被「文本变化自动查询」绕过。
  `clickQuery=false` 表示悬停打开，不是弹菜单；未隐藏主窗口模式也为悬停打开。
  最小字素长度、排除语言和鼠标划词目标窗口已接通；设置页报告原生监听启动错误。
- **迟到快捷键读取修复**：等待系统选区期间发生新划词、编辑或清空时，旧文本、空结果和错误不再覆盖/重开新窗口。
  两项新增回归先在修复前失败（旧文本覆盖与旧空结果清空），修复后通过。
- **测试运行器修复**：原生生命周期用例使测试程序链接到 Tauri 对话框代码，
  缺少 Common Controls v6 manifest 时会在测试启动前报 `0xc0000139`。
  `build.rs` 与库测试入口复用 tauri-build 生成的资源，让单元/集成测试拥有应用相同的 manifest；
  不修改系统 DLL、不新增依赖。

本轮对照来自本机上游源码压缩包解出的文件，不是已确认的发布版本或提交；记录见
[`mac-parity.md`](mac-parity.md)。尚未做 Windows/macOS 并排交互对比。

### 第九轮：多屏定位与实际窗口尺寸（2026-10-18）

- **统一物理坐标**：结果窗不再把桌面坐标除以旧窗口 DPI 后钳至主屏的非负坐标。
  跟随鼠标、居中、右侧以鼠标所在显示器工作区定位；读取失败再退回当前/主显示器，
  不再虚构 1920×1080。跨 DPI 先估算尺寸，移动后重新读取实际边框和尺寸再校正。
- **原版位置语义**：对照 `EZWindowManager.m` 的右侧和居中函数，右侧改为工作区右上角，
  不是垂直居中；工作区原点包括顶部/左侧任务栏。Former 保留可用旧位置，越界或显示器断开后收回可见区域。
  这不等于完成跨重启的窗口位置持久化。
- **尺寸与边框**：调整大小和自动适配改用窗口当前显示器工作区；扣除原生边框后限制客户区，
  不把标题栏高度再加进 `set_size` 的客户区高度。原生最小尺寸优先，极小工作区不保证能容纳整个最小窗口。
  调整后再次校正位置，最大化窗口不自动改动尺寸。
- **自动适配回执**：后端返回实际生效的逻辑客户区宽高，前端据此区分程序调整和手动缩放，
  不再把限高后的迟到 resize 事件误判为手动操作；宽度单独变化也会停止自动适配。

### 第十轮：按需 WebView 与首次操作交接（2026-10-18）

### 第十一轮：隐藏窗口的 WebView 内存回收（2026-10-18）

- **关闭即挂起**：关闭窗口仍只隐藏、不销毁，结果、滚动位置和设置页都保留；隐藏后额外向
  WebView2 申请挂起渲染进程并下调内存目标级别，重新显示前先唤醒。语义等同 Edge 的标签页休眠：
  脚本定时器与动画暂停，渲染进程占用的内存可被系统回收。不新增依赖，不改变窗口生命周期，
  也没有空闲轮询。
- **修正接口归属**：`TrySuspend`、`Resume` 与内存目标级别属于 CoreWebView2 对象
  （`ICoreWebView2_3`、`ICoreWebView2_19`），不属于控制器。上一版把 `ICoreWebView2Controller`
  强转成 `ICoreWebView2_3`，在任何运行时都不可能成功；现在先调用
  `ICoreWebView2Controller::CoreWebView2()`，再在其结果上强转。
- **修正异步派发竞态**：`tauri-runtime-wry` 的 `send_user_message` 在主线程内联执行闭包，
  在工作线程只投递事件（`proxy.send_event`）。上一版在 `with_webview` 返回后立刻读取结果，
  因此无论运行时是否支持都读到初始的 `Unsupported`，隐藏原生测试长期失败。现在 `set_hidden`
  等待自己的请求被事件循环处理（上限 10 秒）后才返回；显示窗口前的唤醒也因此确定在
  `window.show()` 之前完成。
- **拒绝不再伪装**：除「运行时过旧、没有这些接口」以外，其余失败都以错误返回具体原因
  （含 HRESULT 文本）。日志、测量报告和测试因此能区分「被运行时拒绝」与「根本没有提问」。
- **按文档重试一次**：`TrySuspend` 的文档前提是控制器不可见，而隐藏 Tauri 窗口只隐藏 Win32
  窗口、不改控制器可见性。本机运行时 155.0.4283.62 直接接受隐藏窗口的挂起请求，所以只在被
  拒绝时才隐藏 WebView 后重试一次；重试仍失败则恢复可见性，不留下「醒着却不可见」的窗口。
- **隐藏动作仍可执行**：OCR 窗口等需要在不可见时工作的入口先唤醒 WebView，动作送达后若窗口
  仍隐藏，10 秒后再次挂起；可见或获得焦点的窗口不挂起。

原生证据（隐藏窗口、隔离 profile、真实运行时 155.0.4283.62）：集成测试先把控制器设为可见
（复现「窗口曾显示过、再被关闭」这一真实状态），挂起请求被运行时接受、回调返回 `true`，
回读控制器可见性为 `false`；唤醒后回到可见且可运行，进程内窗口数量不变。
覆盖说明：旧版测试从未把 WebView 设为可见，实测即使完全去掉可见性相关处理也会通过，属于
覆盖不足；本轮先把测试加强到「先可见、再挂起、并回读可见性」。
该加强测试在本机仍无法区分「挂起前先隐藏 WebView」这一步：实测本机运行时即使控制器可见也
接受隐藏窗口的挂起请求，因此重试分支只有文档依据，没有本机失败复现。接口归属错误与
异步读取竞态是实测缺陷：修复前测试以 `Unsupported` 失败，修复后通过。

隔离资源测量（`docs/resource-probe-20261018-hidden.json`，Release 探针，2 轮确定性轮换顺序，
静置 10 秒、每轮采样 45 秒；12 轮全部 `stableProcessTree=true`，报告 `status=completed`，

### 第十二轮：`easydict://` 协议注册与冷启动（2026-10-18）

- **协议注册**：新增 `platform/protocol.rs`，启动时把
  `HKCU\Software\Classes\easydict` 写成 Windows 的 URL Protocol 处理器：默认值为显示名、
  `URL Protocol` 存在即标记为协议、`shell\open\command` 写入 `"<本程序路径>" "%1"`。
  这对应 macOS `Info.plist` 的 `CFBundleURLTypes`。写入只针对当前用户、不需要管理员权限，
  也没有新增依赖（复用已有的 `windows` crate，只多开一个 `Win32_System_Registry` 特性）。
  每次启动都会重写，因此程序被移动或便携运行时注册会自愈，不会留下指向旧路径的命令。
- **冷启动**：以前只有单实例回调解析 `argv`，程序**没在运行**时 Windows 直接启动它、
  命令行里的链接被整个丢掉。现在 `setup` 在设置加载完成后解析本进程自己的命令行
  （`std::env::args()`，跳过可执行文件本身），冷启动与「已运行再点链接」走同一个处理函数。
- **修复 `query` 不显示窗口**：`easydict://query?text=…` 过去只把动作塞进目标队列，
  窗口已隐藏或尚未创建时用户什么也看不到（文本要等到下次打开窗口才生效）。现在与 `ocr`
  一样先入队再显示固定窗口；顺序上队列先写入，窗口显示时前端才收到 `action` 事件并按需领取，
  所以首次加载也不会丢文本。
- **不把无关参数当链接**：`easydict://` 前缀按大小写不敏感匹配，容忍 shell 额外加的引号，
  拒绝 `easydict:query`、多字节前缀和 `argv[0]`（可执行文件路径本身）。
- **可逆**：新增 `app.exe --unregister-url-scheme`（退出码 0=已删除、1=本来就没有、2=失败，
  在事件循环之前处理，避免被正在运行的实例转发吞掉）。安装器的
  `installer-hooks.nsh` 在 `NSIS_HOOK_PREUNINSTALL` 里只删除确实指向 `$INSTDIR\app.exe`
  的那条注册，便携版或另一份副本的注册不会被误删。
- **日志不记敏感内容**：只记录路由（`deep link: query`），不记录查询串 ——
  `writeKeyValue` 链接里带的是 API 密钥。

自动化证据（全部在本机实跑）：

### 第十三轮：逐窗口显示配置与窗口几何记忆（2026-10-18）

macOS 原版给每个查询窗口各存一套偏好（`WindowConfigurationKey.swift` 用
`EZConfiguration_<key>_Window<raw>_Key` 生成三个窗口各自的键），并给每个窗口各存一个
`CGRect`（`Defaults.Keys+Extension.swift:260` 的 `windowFrame(for:)`）。这两样此前只搬了
一半：Rust 配置里六个布尔字段齐全，但前端从不读取，界面也没有开关；窗口则完全不留位置。
本轮补齐这两处。

- **逐窗口显示开关真正生效**：新增 `src/hooks/windowSettings.ts`，按窗口类型把
  `inputFieldCellVisibleMain/Mini/Fixed` 与 `selectLanguageCellVisibleMain/Mini/Fixed`
  映射成一处读取（对应上游唯一的读取点 `Configuration+Extension.swift:74`）。
  `QueryWindow` 现在按自己那套值渲染输入框与语言栏；两者都关闭时头部不再留内边距和
  第二条分隔线（`ez-query-head-empty`）。缺失或非布尔值一律按上游默认「显示」处理，
  坏文档不会把输入框吞掉。
- **设置页可改**：高级页新增「逐窗口显示」一节，主窗口 / 迷你窗口 / 侧悬浮窗口
  各两个开关，对应 `WindowConfigurationView.swift` 的两项。
- **窗口几何按窗口类型记忆**：新增 `src-tauri/src/window_frame.rs`。
  `Settings.windowFrames` 以窗口类型为键保存 `{x, y, width, height}`（物理桌面坐标，
  负坐标原样保留）。**尺寸存的是客户区**，与上游存整个 frame 不同：Windows 的
  `set_size` 作用于客户区，如果照上游存外框，每次恢复都会再加一次标题栏和边框，
  窗口会越长越高。移动/缩小时只在内存里记下并交给工作线程，`SETTLE = 500 ms`
  静置后合并成一次落盘，主线程不做磁盘写入；拖拽期间不会一个事件写一次配置。
  以「上次位置」显示固定窗口或迷你窗口时，恢复该窗口自己的位置和尺寸，而不是
  Windows 自己给的创建位置；恢复后仍会按工作区收拢，跨屏/拔屏不会把窗口丢在屏幕外。
  只记录三个查询窗口：OCR 窗口由截图逻辑摆位，设置窗口是普通桌面窗口。
  恢复完成后也会记录一次最终矩形，因此尺寸被限高或收拢后的结果就是下一次恢复的值。
  这一点由原生集成测试盯住：恢复后外框位置、外框尺寸和客户区尺寸都必须与恢复前一致。
- **退出前补写**：`RunEvent::ExitRequested` 调用 `window_frame::flush`，把还在等待静置的矩形

**1. 深链路由在真实系统路径下全部失效（已修复，有真机证据）**

### 第十七轮：几何保存减负与退出补写顺序（2026-10-19）

**实现与可复现证据**

- 新增仅供后端几何路径调用的 `AppState::save_window_frames`，仍与设置编辑共用
  `settings_update` 锁，但只合并矩形及旧版主窗口宽高、加密落盘后更新内存；
  不重建服务/检测器、不刷新托盘、不广播设置。前端没有消费窗口矩形；
  通用设置更新及其广播路径保持不变。无新增依赖或常驻线程。
- 相同矩形不再重复落盘。回归在三次重复保存后比较 DPAPI 文件原始字节保持不变，
  并用同名目录阻止原子替换，验证保存失败不会把未保存的矩形发布到内存，
  解除阻塞后重新记录可正常保存。优化后服务对象替换和设置事件均为 0。
  日志为 `_logs/geometry-cost-after-20261019.log`。
- 原 `flush` 只检查待处理队列：后台线程已取走但尚未写入的批次会被遗漏，
  退出可能早于落盘；补写也可能抢在旧批次前面写入。新增 `WRITING` 锁覆盖
  取队列到提交的完整过程，`flush` 等在途批次后再保存更新的队列；
  不再提前清除 `SAVING`、避免旧工作线程仍活着时启动第二个。
  几何提交自身不再向主事件循环发同步请求。
- 原生回归在并发设置编辑持锁时让几何批次进入后台，再从主事件循环调用 `flush`：
  未落盘前不能返回，放开编辑锁后必须完成，最终磁盘同时保留设置编辑和窗口矩形。
  去掉 `flush` 的 `WRITING` 锁，测试以 `flush returned while a dequeued frame was still unsaved`
